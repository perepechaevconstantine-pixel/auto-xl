# История обновлений — Анализ актов

## v3.1.0 — Система логирования (текущая)
**Папка:** корень репозитория `auto-xl`
**База:** v3.0.2.2
**Статус:** текущая основная ветка

### Новое
- **Структурированное логирование через стандартный `logging`** вместо «сырых» `print()`. Три хендлера:
  - **Консоль** (`StreamHandler` → stderr): уровень из `config.LOG["level"]`, формат `2026-10-23 14:32:07 | INFO  | act_analysis | сообщение`;
  - **`logs/auto-xl.log`** (`RotatingFileHandler`, UTF-8): уровень DEBUG (пишем всё), ротация 5 МБ × 3 бэкапа;
  - **`logs/errors.log`** (`RotatingFileHandler`, UTF-8): только ERROR/CRITICAL, та же ротация.
- **Секция `LOG` и функция `setup_logging(quiet)` в `config.py`** — вся настройка логирования в одном месте (уровень, папка, имена файлов, флаги to_console/to_file, размеры ротации). Повторные вызовы идемпотентны (хендлеры не дублируются).
- **Флаг `--quiet`** — в консоль только ошибки; файлы логов пишутся по-прежнему полностью. Финальный результат (`Готово за N с...`) печатается в консоль всегда, даже в тихом режиме.
- **Замеры времени ключевых этапов**: загрузка файлов (по каждому ПК + суммарно), обработка/парсинг данных, запись результата в Excel — в лог на уровне INFO.
- **Логирование конфигурации при старте**: аргументы запуска (`logger.info`), секция `LOG` и шаблоны путей (`logger.debug`).
- **Traceback ошибок** попадает в оба файла логов: предупреждения об отсутствующих источниках — `logger.warning(exc_info=True)`, критический обработчик в `__main__` — `logger.critical(exc_info=True)` (старый механизм `error_<timestamp>.log` убран, его полностью заменяет `errors.log`).

### Изменено
- `print()` заменён на `logger.*` во всех служебных сообщениях (`load_config`, `ensure_paths_interactive`, `load_pc`, `die`). Оставлены только: версия первой строкой, финальный результат и текст критической ошибки (для интерактивного запуска двойным кликом).
- `install.bat`: создаёт папку `logs/` при установке; версия в шапке — v3.1.0.
- `.gitignore`: добавлены `logs/*.log`, `logs/*.log.*`, `last_error.txt` (сама папка `logs/` уже игнорировалась).

### Проверено
- Сценарии ТЗ: level=DEBUG (консоль всё / errors.log пуст), level=ERROR (консоль только ошибки / файл всё), `--quiet` (консоль ERROR+ / файлы полные), traceback в оба файла, ротация (`auto-xl.log.1..3`), идемпотентность `setup_logging()`, формат строки лога.

## v3.0.2.1 — Фикс установщика (install.bat)

### Исправлено
- **install.bat больше не полагается на «heredoc» из `echo`-строк** — генерация временных Python-скриптов через многострочный блок `( echo ... ) > file.py` оказалась хрупкой: `^(` экранируется парсером cmd только вне кавычек, а внутри одинарных кавычек Python (`__import__('m')`) скобки и так не требуют защиты. В результате в `_check_imports.py` попадал битый код (`__import(m)`, `sys.exit(1)` без кавычек), проверка библиотек всегда падала с ошибкой компиляции, а сам файл мог не создаваться.
- Проверки вынесены в **настоящие файлы `_check_imports.py` и `_check_excel.py`**, которые лежат рядом с `install.bat` и копируются в рабочую директорию командой `copy`. Никакого inline-кода в батнике.
- Добавлена явная проверка существования `_check_imports.py` с понятным сообщением об ошибке.
- `_check_excel.py` корректно обрабатывает отсутствие pywin32 (`ImportError`) — печатает INFO вместо падения.

## v3.0.1 — Портативная конфигурация
**Папка:** корень репозитория `auto-xl`
**База:** v3.0.0
**Статус:** заменена на v3.0.2

### Новое
- **Конфигурация через `config.py` / `config.json`** — сетевые пути к источникам больше не зашиты в код.
  - `config.json` — сохраняемые пути (создаётся автоматически при первом запуске);
  - если файла нет, скрипт спрашивает папки у пользователя (диалог выбора папки, fallback — ввод путём), сохраняет и продолжает;
  - CLI-аргументы `--gp PATH` / `--ob PATH` переопределяют конфиг (для макросов и отладки);
  - в `config.py` можно задать пути `GP_PATH_TEMPLATE` / `OB_PATH_TEMPLATE` жёстко — они имеют приоритет над `config.json`.
- **Папка `logs/`** — каждая ошибка дублируется в `logs/error_YYYY-MM-DD_HHMMSS.log` (плюс старый `last_error.txt`).
- Версия поднята до **3.0.1**, явно указана в модуле (`VERSION = "3.0.1"`).

## v3.0.0 — Основная ветка разработки
**Папка:** `Анализ актов_v3.0.0`
**База:** v2.9.9 (ветка `Общ_Сводная`)
**Статус:** восстановлена из «Истории обновлений» после потери исходного кода (никогда не была в Git)

### Оптимизации и точность
- **Параллельное чтение источников** — чтение файлов ГП для разных ПК выполняется одновременно через `ThreadPoolExecutor`, а не последовательно
- **Отключение `EnableEvents`** — события Excel выключены во время записи, нет лишних срабатываний обработчиков событий
- **Отключение `DisplayAlerts`** — подавление диалоговых окон Excel во время операции
- **Пакетная подсветка столбца B** — ячейки столбца B окрашиваются блоками одного цвета, а не по одной — значительно меньше вызовов COM к Excel
- **Точные денежные расчёты через `decimal.Decimal`** — все суммы и разности считаются в `Decimal` с арифметическим округлением (`ROUND_HALF_UP`) до 2 знаков. Исключаются ошибки плавающей точки (`float`) и накопление погрешностей при сложных вычислениях. Это критично для строительных и финансовых расчётов объёмов.
- **Сохранение/восстановление состояния** — исходные значения `Calculation`/`EnableEvents`/`DisplayAlerts` сохраняются перед изменением и восстанавливаются после завершения

### Функциональные улучшения (унаследовано от v2.9.9, ветка Общ_Сводная)
- Акт отображается, если он есть в **Общей сводной**, даже если отсутствует в **Сводной ГП**
- Столбец **G «DP»** между «КМ» и «Статусы»
- Устойчивая обработка пропусков в столбце B (пустые ячейки между актами)
- Порядковые номера в столбце A только для непустых актов
- Автофильтр на строке 2, охватывающий все заполненные столбцы (до AB)

### Исправленные ошибки
- **`AttributeError: 'int' object has no attribute 'quantize'`** — счётчики марок (`cnt`, `o_cnt`) оставались типом `int` и не имели метода `.quantize()`. Функция `dec2()` теперь приводит любое значение (`int`, `float`, `str`, `Decimal`) к `Decimal` перед квантованием; нечисловые значения трактуются как `0.00`. Дополнительно счётчики в `read_gp()` и `read_ob()` переведены на `Decimal` для единообразия типов.

### Логика соответствия источникам
| Акт в Сводной ГП | Акт в Общей сводной | Результат |
|------------------|---------------------|-----------|
| Есть | Есть | Данные из обоих источников |
| Нет | Есть | Данные из Общей сводной; ГП = нули, G «DP» = `—`, статус `(нет в Сводной ГП)` |
| Есть | Нет | Данные из Сводной ГП; Общая сводная = нули |
| Нет | Нет | `НЕ НАЙДЕНО` |

- Метизы читаются независимо от наличия акта в Сводной ГП.

## Общие требования ко всем версиям
- Windows 10 / 11
- Python 3.10+
- Microsoft Excel (COM через `pywin32`)
- Библиотеки: `python-calamine>=0.8.2`, `openpyxl>=3.1.5`, `pywin32>=306`
- Сетевой доступ к папкам с `.xlsb` источниками (с v3.0.1 настраиваются в `config.py` / `config.json`)
